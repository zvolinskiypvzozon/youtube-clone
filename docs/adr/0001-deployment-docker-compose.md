# ADR 0001: Деплой — docker compose и одна команда `deploy.sh`

- Статус: принято
- Дата: 2026-11-07

## Контекст

Проверяющий разворачивает систему на чистой Ubuntu 24.04 (HTTP по IP, интернет есть).
Должны подняться приложение, БД, хранилище и фоновая обработка, и сразу работать
сценарий «регистрация → загрузка → просмотр → лайк и комментарий».

## Решение

- Весь стек описан в одном `docker-compose.yml`. `deploy.sh`:
  1. ставит Docker Engine и Compose plugin из официального репозитория Docker, если их нет;
  2. генерирует `.env` со случайными секретами (`scripts/gen-env.sh`; существующий файл не трогает);
  3. запускает `docker compose up -d --build` и ждёт `/api/health`;
  4. загружает демо-данные (флаг `--no-seed` отключает) и печатает URL.
- Скрипт идемпотентен: повторный запуск обновляет стек и сохраняет данные.
- Миграции и инициализация хранилища вынесены в одноразовые сервисы. api и worker ждут их
  успешного завершения (`service_completed_successfully`).
- Наружу публикуется только `web` (nginx). Postgres и хранилище доступны лишь во внутренней сети.
- Образы закреплены до patch-версии (хранилище — по точному релизу), Python/npm-зависимости — точными
  версиями (`requirements.txt`, `package-lock.json`). Пакеты Docker Engine ставятся актуальные стабильные.

## Альтернативы

- **Ansible / bare-metal systemd**: больше кода, хуже воспроизводимость, дольше проверять.
- **Kubernetes (k3s)**: избыточно для одной ВМ, установка займёт больше, чем весь деплой compose.

## Последствия

- Для первого запуска нужен интернет: пакеты Docker, образы, pip/npm при сборке.
- Обновление выполняется командой `git pull && sudo ./deploy.sh`.
