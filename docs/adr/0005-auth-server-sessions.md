# ADR 0005: Аутентификация — серверные сессии в HttpOnly cookie

- Статус: принято
- Дата: 2026-11-07

## Решение

- После входа сервер создаёт случайный токен (256 бит). В таблице `sessions` хранится только
  SHA-256 хэш токена, срок жизни и метаданные (IP, User-Agent).
- Cookie `session`: `HttpOnly`, `SameSite=Lax`, `Path=/` (`Secure` — при HTTPS, переключается конфигом).
- Выход и бан пользователя удаляют сессии в БД, отзыв мгновенный.
- CSRF: изменяющие запросы требуют заголовок `X-CSRF-Token`, совпадающий с cookie `csrf`
  (double submit). Вместе с `SameSite=Lax` этого достаточно для SPA на том же origin.
- Пароли хэшируются argon2id.
- Для Swagger поддерживается `Authorization: Bearer <token>` (тот же токен сессии).

## Альтернативы

- **JWT access + refresh**: stateless, но мгновенный отзыв (бан, выход) всё равно требует
  хранилища, а хранение токена в JS открывает его для XSS.

## Последствия

- Каждый аутентифицированный запрос обращается к БД за сессией: один запрос по индексу,
  для этой нагрузки приемлемо.
