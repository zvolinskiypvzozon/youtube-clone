# Проверка деплоя на чистой Ubuntu 24.04

Цель: убедиться, что `sudo ./deploy.sh` на системе «из коробки» поднимает весь стек (K1),
и повторить это сколько угодно раз с одного и того же чистого состояния.

Основной способ — отдельный дистрибутив WSL `yt-clean`, который сбрасывается из tar-снимка.
Запасной вариант — ВМ VirtualBox со снимком (раздел в конце).

## Способ 1: WSL-дистрибутив `yt-clean`

### Подготовка (один раз, PowerShell на Windows)

Снимок и файлы дистрибутива лежат в `$HOME\wsl\` профиля Windows
(у автора — `C:\Users\Федор\wsl\`). Каталог создаётся один раз: `mkdir $HOME\wsl`.

```powershell
# Чистая Ubuntu 24.04 отдельным дистрибутивом
wsl --install -d Ubuntu-24.04 --name yt-clean
# Внутри: создать пользователя по запросу установщика, больше ничего не ставить.
# Проверить, что systemd включён (на свежих образах Ubuntu — по умолчанию):
#   cat /etc/wsl.conf   ->  [boot] systemd=true

wsl --terminate yt-clean
wsl --export yt-clean $HOME\wsl\yt-clean.tar      # эталонное «чистое» состояние
```

### Сброс к чистому состоянию (перед каждой проверкой)

```powershell
wsl --unregister yt-clean
wsl --import yt-clean $HOME\wsl\yt-clean $HOME\wsl\yt-clean.tar
```

После `--import` дистрибутив запускается под root, если в `/etc/wsl.conf` нет секции
`[user] default=<имя>`. Для проверки это не важно: `deploy.sh` всё равно работает от root.

### Перед запуском: общий сетевой стек WSL2

Все дистрибутивы WSL2 работают в одной служебной ВМ и **делят одно сетевое пространство имён**
(общие порты, интерфейсы, iptables). Отсюда два требования:

1. **Порт 80 свободен.** Его не должен занимать стек проекта или что-то другое в любом дистрибутиве.
   Проверка: `ss -ltn 'sport = :80'` — вывод должен быть пустым.
2. **Docker в других дистрибутивах остановлен.** Второй `dockerd` в `yt-clean` делил бы с первым
   мост `docker0` и правила iptables. Возможны сбои, не связанные с проектом. В рабочем дистрибутиве:
   ```bash
   docker compose down            # стек проекта (без -v — данные сохраняются)
   sudo systemctl stop docker docker.socket
   ```
   После проверки: `sudo systemctl start docker`.

### Запуск

```powershell
wsl -d yt-clean
```
```bash
git clone https://github.com/zvolinskiypvzozon/youtube-clone
cd youtube-clone
time sudo ./deploy.sh
```

### Критерии успеха

- Скрипт завершился с кодом 0, сообщения «Готово» и адреса выведены.
  Первый запуск — несколько минут: установка Docker, скачивание образов, сборка.
- С Windows в браузере открываются `http://localhost/`, `http://localhost/docs`,
  `http://localhost/api/health` → `{"status":"ok","database":"ok","storage":"ok"}`.
  Адрес из вывода скрипта (`hostname -I`) — внутренний адрес WSL. С Windows используйте `localhost`.
- Повторный `sudo ./deploy.sh` проходит без ошибок, данные сохраняются.
- Сценарий `scripts/smoke.sh http://localhost` проходит целиком (появится вместе с загрузкой видео).

### Что прислать при ошибке

- последние ~30 строк вывода `deploy.sh` и время выполнения;
- `sudo docker compose ps -a`;
- `sudo docker compose logs --tail=100 <упавший сервис>`.

### Чем WSL отличается от настоящего сервера

| Аспект | WSL `yt-clean` | Ubuntu Server (ВМ, облако) |
|---|---|---|
| Ядро | общее ядро WSL (Microsoft) | собственное ядро Ubuntu |
| Сеть | общая с другими дистрибутивами, доступ с Windows по `localhost` | собственный IP |
| systemd | включается через `/etc/wsl.conf`; без него `deploy.sh` запускает Docker через `service` | есть всегда |
| unattended-upgrades сразу после загрузки | обычно не работает | работает; `deploy.sh` ждёт блокировку dpkg до 10 минут |

Проверка в WSL покрывает основное: установку Docker, сборку, запуск, миграции, хранилище, nginx.
Сетевую часть настоящего сервера (доступ по IP из локальной сети) она не покрывает. Перед сдачей
желателен один прогон на ВМ (способ 2).

## Способ 2: ВМ VirtualBox (запасной, перед сдачей)

1. ВМ Ubuntu 24.04 Server, сеть «Сетевой мост», снимок `clean` сразу после установки.
2. Восстановить снимок `clean`, зайти по SSH, выполнить те же команды из раздела «Запуск».
3. Проверка с хоста: `http://<IP ВМ>/`, `/docs`, `/api/health`. IP выводит `deploy.sh`.
