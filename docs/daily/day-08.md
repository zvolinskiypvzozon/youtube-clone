## Шаги 1–5 — главное

- **Плеер.** На ошибку источника (истёкшая presigned-ссылка → 403, `<video>` код не сообщает)
  заново запрашивает `/stream`, продолжает с той же позиции и состояния паузы; не больше 3
  повторов подряд без продвижения, со 2-го — пауза 1 с, во время перезапроса новые `error`
  игнорируются. Проверено в Chrome: 403 на старую подпись посреди просмотра → новая подпись →
  продолжение с 59,6 с.
- **Смена сессии** (вход, выход, 401, другой пользователь в `/me`) сбрасывает данные прежней
  сессии; открытая страница видео перезапрашивается без размонтирования плеера. Смена
  пользователя через `/me` раньше кэш не сбрасывала — баг дня 7, найден аудитом (Medium),
  `cdf3dfb`.
- **Комментарии** выводятся только текстом; счётчик берётся с сервера (комментарии забаненных
  он не считает); правки кэша отменяют идущую подгрузку страницы.
- **Загрузка**: ссылки частей — только в `/yt-raw/` после разбора URL-парсером (`..`,
  `%2e%2e`); `complete` с повтором и сверкой по карточке (иначе дубль при потерянном ответе);
  отмена, ошибка и уход со страницы удаляют незавершённую загрузку.
- **Вызовы API** сверяются со схемой OpenAPI при компиляции (`api()` в `src/api/typed.ts`):
  метод, путь, параметры, тело (в том числе необязательное) и ответ; ключи моков в тестах — тоже.
- **Модерация**: `/moderation` — только staff, остальным «Страница не найдена»; права на каждое
  действие проверяет API; после действия — фокус на заголовок, объявление, обновление всего
  затронутого, в том числе при 409.

**Исправлено** в `5a3f2cc`:
- метод бана — `PUT`;

  со `schema.d.ts` на этапе компиляции; ключи моков в тестах — тоже по схеме; прямой
  `request()` запрещён ESLint;
- проверено: мутации «`post` в клиенте» и «`POST` в моке» ломают `tsc`; все прежние вызовы
  (видео, реакции, подписка, жалобы, комментарии, загрузка, «Мои видео», допуск) сверены —
  других расхождений нет; бан из комментария в Chrome — `PUT` → 200.

После исправления архитектор повторил бан руками — работает.

## Проблемы

- **Метод бана (405)** — нашла ручная проверка, тесты были «согласны» с ошибкой (см. выше).
- **Тест, проходивший случайно.** Тест порядка частей загрузки зависел от таймеров и под
  нагрузкой проходил без сортировки результата — мутация это показала; переписан на явное
  управление порядком ответов.
- **Обвязка тестов** (`renderApp`) затирала настройки запросов приложения
  (`refetchOnWindowFocus: false`) — тест смены пользователя проходил и без исправления.
  Мутация показала, обвязка исправлена, весь набор мутаций перепроверен.
- **Пробел, принятый как невоспроизводимый, оказался багом** (удаление плейлиста): тест
  удаления стал изредка падать на шаге 5 — исправлено `3a44476`.
- **Проверочная команда с удалением** (`git worktree remove --force`) выполнилась после
  неудачного предыдущего шага (связка через `;`). Удалилась только временная копия, уже
  сверенная с коммитом; проверка повторена на чистой копии. Вывод: шаги с удалением — только
  через `&&`.
- Скрипты проверки в браузере несколько раз падали на неоднозначных селекторах — правились
  скрипты, не приложение.

## Известные пробелы

- **Отмена между последней частью и `complete` не покрыта тестом** (шаг 3). Защита есть:
  `UploadPage` проверяет `controller.signal.aborted` после `uploadParts` и до `finishUpload`;
  при отмене бросается `AbortError`, незавершённая загрузка удаляется. Окно — между
  завершением последнего `PUT` и перерисовкой в «Завершаем загрузку»; надёжно воспроизвести
  его в jsdom не удалось. Мутация этой строки не ловится — пробел принят архитектором
  (2026-11-12). Последствие без защиты: пользователь нажал «Отменить», а видео всё равно
  ушло в обработку (его можно удалить в «Моих видео»).
- ~~Порядок «переход → удаление из кэша» при удалении плейлиста не покрыт тестом~~ (шаг 4) —
  **воспроизведён и закрыт** коммитом `3a44476`. Пробел был принят архитектором (2026-11-12) как
  невоспроизводимый, но на шаге 5 тест удаления стал изредка видеть 2 запроса вместо 1.
  Причина: переход React Router 7 идёт с низким приоритетом, страница ещё смонтирована, а
  инвалидация списков по префиксу `["playlist"]` задевала и удалённый плейлист — он
  перезапрашивался (404, мелькание «Плейлист не найден»). Исправление: его ключи только
  помечаются устаревшими (`refetchType: "none"`), остальные списки обновляются. Тест стабилен
  (8/8), мутация «инвалидировать и удалённый плейлист» теперь ловится (3/3 и в полном наборе).
- Владелец видео забанен — staff видит форму комментария, сервер ответит 409 (признака бана
  владельца в `VideoStateOut` нет).
- Страница «не найдена» без `h1` (заголовок — абзацем); замечено при проверке экранов.
