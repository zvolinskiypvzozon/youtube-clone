## Решения архитектора (2026-11-09)

- **Перезапрос ссылки при 403** (продолжение с `currentTime`, TTL 15 мин) — **день 7**, в
  компоненте плеера, с тестом. Бэкенд готов (`/stream`, `expires_in`).
- **Плейлисты — день 6**, вместе с модерацией, минимальные: создать, добавить и убрать своё
  видео, список на канале, K4 (в ТЗ плейлисты на экране канала — фронтенду нужен API).
- **Просмотры без дедупликации на сервере** — *упрощение*: плеер шлёт один запрос после 5 с
  воспроизведения; накрутку ограничивает rate limit дня 6 (`limit_req`).
- **Реакции и новые комментарии — только к не скрытому видео** (`policies.can_interact`, ADR
  0006 доп. 4), для всех, включая владельца и staff: это публичное голосование, а доступ staff
  к скрытому — для разбора. Видящим скрытое — 409 с причиной; читать комментарии — по `can_view`.
- **`limit_req` для просмотров — день 6**, вместе с остальным rate limit (не отдельной зоной
  сейчас). Просмотры владельца своего видео засчитываются (как сейчас).
- **Принятые упрощения:** комментарии плоские (без ответов и правки); лента подписок и
  «Понравившиеся» — день 9 вместе с историей.

## Решения архитектора (2026-11-10)

- **Подписки:** `GET /api/me/subscriptions` — сейчас, минимально (каналы с пагинацией, без
  ленты видео — день 9); список подписчиков канала наружу не отдаётся, только счётчик; свои
  подписки видит только сам пользователь. Аудит для шага 3 не нужен при этом условии.
- **На день 6:** невидимые символы — 422, если после их удаления текст пустой; символы
  направления (U+202A–U+202E, U+2066–U+2069) вырезать — для комментариев, названия и описания
  видео. Комментарии забаненного скрываются из выдачи (не удаляются); счётчики пересчитываются
  при бане и разбане тем же кодом, что при удалении пользователя.
- **Поиск:** порядок — новые сверху, релевантность — в отчёт как упрощение; аудит шага 4
  параллельно с ревью.
- **На день 6 (после шага 3):** одно правило для всего контента забаненного — его канал
  отвечает 404, как скрыты и его комментарии; подписаться на него нельзя.

- **Удаление комментариев:** автор или владелец видео; staff — через модерацию дня 6;
  под скрытым видео удалять можно; автор удаляет своё и после потери допуска; не виден —
  404, виден без прав — 403 (ADR 0006 доп. 5).
- **NUL в тексте комментария — 422** с тестом (в 3b NUL давал 500).
- **Комментарии выводятся только как текст**, без `dangerouslySetInnerHTML` — в `security.md`
  и в план дня 7.
- **Rate limit на `POST` комментариев — день 6**, вместе с остальным `limit_req`.

## Шаг 1 — лайки (K6)

`reactions` (PK `video_id, user_id`, enum `reaction_kind`, индекс `(user_id, kind, created_at
DESC)`) и миграция `feae87d73a60`. `PUT`/`DELETE /api/videos/{id}/reaction` →
`{my_reaction, likes_count, dislikes_count}`; `my_reaction` в карточке. Доступ — `can_view`
(404), только готовое (409). Изменение — под блокировкой строки видео после проверки прав;
права и готовность под ней перепроверяются; прежняя реакция читается под блокировкой, счётчики
меняются на разницу. Повтор той же реакции — без блокировки.

Проверки: pytest **479** зелёных, ruff чистый. Мутации 4 из 4 ловятся (применение — `diff -r`):
без `can_view` → матрица, «404 неотличимы», перепроверка; без блокировки строки → обе гонки,
перепроверка, «удалено, пока ждали»; без проверки «готово» → матрица (owner, moderator,
admin); без перепроверки прав под блокировкой → «стало приватным, пока ждали».

Ревью (CHANGES REQUESTED) и аудит (Critical/High/Medium нет) — исправлено: смена реакции
обновляет `created_at`; права и готовность перепроверяются под блокировкой; повтор той же
реакции — без блокировки; лайк не сдвигает `videos.updated_at`; индекс с `kind`; 503 в OpenAPI;
тесты «удалено/стало приватным, пока ждали». Известное ограничение — «горячая» строка `videos`
у популярного видео (`db.md`).

Решение архитектора по открытому вопросу — `can_interact`: на скрытом видео реакции не ставит
никто (409), проверка повторяется под блокировкой. Мутации: правило без модерации → матрица
и оба теста скрытого; без повторной проверки под блокировкой → «скрыли, пока лайк ждал».

## Шаг 2 — комментарии

`comments` (`id`, `video_id`, `author_id`, `body` — CHECK 1–2000 после `btrim`, индексы
`(video_id, created_at DESC, id DESC)` и `(author_id)`), миграция `685d115152a1`.
`GET /api/videos/{id}/comments` (keyset, новые сверху, `can_delete` у каждого),
`POST /api/videos/{id}/comments` → 201, `DELETE /api/comments/{id}` → 204. Права — ADR 0006
доп. 5: читать — `can_view`; писать — `can_view` + `can_interact`; удалять — автор или
владелец видео (`policies.can_delete_comment`), невидимый — 404, видимый без прав — 403.
Счётчик: `POST` — атомарный `UPDATE comments_count + 1` с `visible_filter` +
`interactable_filter` в самом запросе, затем `INSERT`; `DELETE` — порядок «видео →
комментарий», −1 только если `DELETE … RETURNING` удалил строку. NUL в тексте — 422 (тест).

Проверки: pytest — 43 теста комментариев; ruff чистый; миграция `downgrade -1` / `upgrade`
на dev-БД. Мутации 7 из 7 ловятся (применение — `diff -r`): без `can_view` в `GET` →
матрица чтения и «404 неотличимы»; без `interactable_filter` в `UPDATE` → «скрыли, пока
ждал»; без `visible_filter` → «стало приватным, пока ждал»; удалять может любой → 403-тесты;
403 вместо 404 для невидимого → «неотличим от несуществующего»; счётчик чтением в Python →
«20 параллельных»; −1 без `RETURNING` → «два параллельных удаления».

Тесты нашли баг до ревью: в запасной ветке `POST` (0 строк в `UPDATE`) `rollback` просрочивал
`viewer` → `MissingGreenlet` (500); теперь `expire` строки видео без rollback. Второй
ожидающий строки ждёт первого (tuple lock), а не держателя — помощник
`wait_for_lock_queue` считает очередь по цепочке.

Ревью (APPROVE) и аудит (Critical/High/Medium нет): добавлен тест ветки 503 «состояние
вернулось обратно»; боковой канал по времени в `DELETE` (Low) и невидимые/bidi-символы
(Low) — в «Принятые риски» `security.md`; «горячая» строка видео — rate limit дня 6.
Комментарии забаненных остаются в выдаче — вопрос модерации дня 6.

## Шаг 3 — подписки

`subscriptions` (PK `channel_id, user_id`, индекс `(user_id, created_at DESC, channel_id
DESC)`), миграция `6507f3ac93de`. `PUT`/`DELETE /api/channels/{handle}/subscription` →
`{subscribed, subscribers_count}` (идемпотентно), `subscribed` в карточке канала,
`GET /api/me/subscriptions` (каналы, keyset; лента видео подписок — день 9). Свой канал —
400. Счётчик без блокировки строки канала: меняется, только если `INSERT … ON CONFLICT DO
NOTHING RETURNING` / `DELETE … RETURNING` изменил состояние именно этим запросом.

Условия архитектора выполнены тестами: подписка на свой канал → 400; параллельные подписки
и отписки (20 разных пользователей, 10 повторов одного, смесь PUT/DELETE) — счётчик равен
числу строк; подписка не открывает приватные видео (карточка, поток, комментарии, список
канала; контроль — с допуском открывается); подписчики канала наружу не отдаются (карточка
даже владельцу — только счётчик), чужие подписки не видны, в OpenAPI нет эндпоинта
подписчиков.

Мутации 5 из 5 ловятся (применение — `diff -r`): без проверки «свой канал» → 400-тест; +1 и
−1 без условия `RETURNING` → повторы и 10 параллельных одного пользователя; счётчик чтением
в Python → 20 параллельных; «Мои подписки» без фильтра по пользователю → «чужие не видны».

Ревью (APPROVE), исправлено: при «нет изменений» счётчик в ответе перечитывается (иначе
проигравший параллельный `PUT` отвечал «подписан, подписчиков 0»), тест проверяет тела
ответов; тесты каскада при удалении подписчика и владельца канала; keyset с одинаковым
`created_at`; «горячая» строка `channels` — в известных ограничениях `db.md`. Аудит по решению
архитектора не проводился.

## Шаг 4 — поиск

`GET /api/videos?q=` — подстрока в названии без учёта регистра (`ILIKE … ESCAPE '\'`, ввод
экранируется в `repositories/videos.escape_like`: `%`, `_`, `\` — буквально), тот же
каталог и keyset, что у ленты: только `listed_filter` (K3, K4), одинаково для любого зрителя.
`q` — 1–100 символов после обрезки, пусто и NUL → 422. Миграция не нужна
(`ix_videos_title_trgm` был с дня 2). **Упрощение:** порядок — новые сверху, без ранжирования
по релевантности (несовместимо с keyset; решение архитектора 2026-11-10); поиск только по
названию.

Проверки: 19 тестов поиска (матрица 6 зрителей × 6 состояний — находится только public;
`%`/`_`/`\`; регистр и кириллица; описание не ищется; пагинация; 422; план без Seq Scan).
Мутации 2 из 2 ловятся: без `listed_filter` → матрица; без экранирования → тесты шаблонов.

Ревью (APPROVE) — добавлен тест «описание не ищется». Аудит (Critical/High/Medium нет): два
Low в «Принятые риски» `security.md` — короткий или пустой по результату запрос проходит
каталог по `ix_videos_feed` (O(N), без `statement_timeout`) и теоретический тайминг через
триграммный индекс; предложение на день 6 — зона `limit_req` для поиска и `statement_timeout`.

Полный прогон после шага выявил хрупкий тест `test_feed_uses_partial_index`: план зависел от
статистики автоанализа (новые тесты поиска наполняют `videos` раньше `test_videos`), и
planner выбрал `ix_videos_channel_published` + Sort. Отдельно тест проходил. Исправлено: тест
проверяет, что частичный индекс даёт порядок выдачи, — с `enable_sort = off`
(`generic_plan(no_sort=True)`).

## Шаг 5 — просмотры

`POST /api/videos/{id}/view` → 204, вход не нужен. Доступ — `can_view` (404); не готово — 409;
скрытое модератором — 204 без засчитывания (владелец и staff открывают его для разбора).
Счётчик — атомарный `UPDATE` с условиями политики в самом запросе (`visible_filter(viewer)` +
`policies.interactable_filter()`), `updated_at` не меняется. **Упрощение:** без дедупликации на
сервере — плеер шлёт один запрос после 5 с воспроизведения, накрутку ограничит rate limit дня 6.

Проверки: мутации 4 из 4 ловятся — без `can_view` → матрица и «404 неотличимы»; без
`interactable_filter` → скрытое засчитывается (матрица: owner, moderator, admin); без
`visible_filter` в `UPDATE` → «стало приватным, пока ждал»; инкремент чтением и записью в
Python → «20 параллельных без потерь» и гонка.

Ревью (CHANGES REQUESTED) и аудит (Critical/High нет) — исправлено: условия политики перенесены
в сам `UPDATE` (`policies.interactable_filter` — SQL-аналог `can_interact`; копия правила в
репозитории убрана), тест «стало приватным, пока ждал»; ADR 0006 доп. 4 — пункт про просмотры
(скрытое → 204 без счёта, окно отзыва допуска принято); накрутка (Medium, аудит) — в «Принятые
риски» `security.md` с фактическим пределом 20 r/s с IP до дня 6.
