## Решения архитектора (2026-11-09)

- **Перезапрос ссылки при 403** (продолжение с `currentTime`, TTL 15 мин) — **день 7**, в
  компоненте плеера, с тестом. Бэкенд готов (`/stream`, `expires_in`).
- **Плейлисты — день 6**, вместе с модерацией, минимальные: создать, добавить и убрать своё
  видео, список на канале, K4 (в ТЗ плейлисты на экране канала — фронтенду нужен API).
- **Просмотры без дедупликации на сервере** — *упрощение*: плеер шлёт один запрос после 5 с
  воспроизведения; накрутку ограничивает rate limit дня 6 (`limit_req`).
- **Реакции и новые комментарии — только к не скрытому видео** (`policies.can_interact`, ADR
  0006 доп. 4), для всех, включая владельца и staff: это публичное голосование, а доступ staff
  к скрытому — для разбора. Видящим скрытое — 409 с причиной; читать комментарии — по `can_view`.
- **`limit_req` для просмотров — день 6**, вместе с остальным rate limit (не отдельной зоной
  сейчас). Просмотры владельца своего видео засчитываются (как сейчас).
- **Принятые упрощения:** комментарии плоские (без ответов и правки); лента подписок и
  «Понравившиеся» — день 9 вместе с историей.

## Шаг 1 — лайки (K6)

`reactions` (PK `video_id, user_id`, enum `reaction_kind`, индекс `(user_id, kind, created_at
DESC)`) и миграция `feae87d73a60`. `PUT`/`DELETE /api/videos/{id}/reaction` →
`{my_reaction, likes_count, dislikes_count}`; `my_reaction` в карточке. Доступ — `can_view`
(404), только готовое (409). Изменение — под блокировкой строки видео после проверки прав;
права и готовность под ней перепроверяются; прежняя реакция читается под блокировкой, счётчики
меняются на разницу. Повтор той же реакции — без блокировки.

Проверки: pytest **479** зелёных, ruff чистый. Мутации 4 из 4 ловятся (применение — `diff -r`):
без `can_view` → матрица, «404 неотличимы», перепроверка; без блокировки строки → обе гонки,
перепроверка, «удалено, пока ждали»; без проверки «готово» → матрица (owner, moderator,
admin); без перепроверки прав под блокировкой → «стало приватным, пока ждали».

Ревью (CHANGES REQUESTED) и аудит (Critical/High/Medium нет) — исправлено: смена реакции
обновляет `created_at`; права и готовность перепроверяются под блокировкой; повтор той же
реакции — без блокировки; лайк не сдвигает `videos.updated_at`; индекс с `kind`; 503 в OpenAPI;
тесты «удалено/стало приватным, пока ждали». Известное ограничение — «горячая» строка `videos`
у популярного видео (`db.md`).

Решение архитектора по открытому вопросу — `can_interact`: на скрытом видео реакции не ставит
никто (409), проверка повторяется под блокировкой. Мутации: правило без модерации → матрица
и оба теста скрытого; без повторной проверки под блокировкой → «скрыли, пока лайк ждал».

## Шаг 5 — просмотры

`POST /api/videos/{id}/view` → 204, вход не нужен. Доступ — `can_view` (404); не готово — 409;
скрытое модератором — 204 без засчитывания (владелец и staff открывают его для разбора).
Счётчик — атомарный `UPDATE` с условиями политики в самом запросе (`visible_filter(viewer)` +
`policies.interactable_filter()`), `updated_at` не меняется. **Упрощение:** без дедупликации на
сервере — плеер шлёт один запрос после 5 с воспроизведения, накрутку ограничит rate limit дня 6.

Проверки: мутации 4 из 4 ловятся — без `can_view` → матрица и «404 неотличимы»; без
`interactable_filter` → скрытое засчитывается (матрица: owner, moderator, admin); без
`visible_filter` в `UPDATE` → «стало приватным, пока ждал»; инкремент чтением и записью в
Python → «20 параллельных без потерь» и гонка.

Ревью (CHANGES REQUESTED) и аудит (Critical/High нет) — исправлено: условия политики перенесены
в сам `UPDATE` (`policies.interactable_filter` — SQL-аналог `can_interact`; копия правила в
репозитории убрана), тест «стало приватным, пока ждал»; ADR 0006 доп. 4 — пункт про просмотры
(скрытое → 204 без счёта, окно отзыва допуска принято); накрутка (Medium, аудит) — в «Принятые
риски» `security.md` с фактическим пределом 20 r/s с IP до дня 6.
