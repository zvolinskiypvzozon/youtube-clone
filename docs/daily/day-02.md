## Решения архитектора

- **Дата публикации** как на YouTube: момент первой публикации (видео готово и не приватно),
  потом не меняется.
- **Выход идемпотентен:** 204 и очистка cookie даже без действующей сессии.
- **Формат 422:** `detail` — строка для показа пользователю, `errors` — список полей.
- **Первый администратор:** логин и пароль в `.env`, пароль один раз печатается `deploy.sh`.
  Демо-учётки появятся вместе с seed, с предупреждением, что они только для проверки.

## Проблемы и как решены

1. **Docker остановлен после проверки в yt-clean.** Модели писались без БД, миграция
   сгенерирована после запуска Docker архитектором.
2. **Ловушки SQLAlchemy в async**, все пойманы тестами:
   - `updated_at` после UPDATE «протухал», чтение давало `MissingGreenlet` (500 в API).
     Лечится `eager_defaults=True`;
   - удаление пользователя через ORM падало на NOT NULL. Лечится `passive_deletes=True`,
     каскад делает БД;
   - `rollback()` помечает загруженные объекты устаревшими даже при `expire_on_commit=False`.
     Транзакции только для чтения закрываются `commit()`.
3. **Хук ruff между двумя правками одного файла** удалял «неиспользуемый» импорт, добавленный
   первой правкой. Правки, которые зависят друг от друга, делаются за один раз.
4. **Собственные deny-правила блокировали правки агента**, если в тексте встречалось `grep … .env`.
   Правила работают как задумано. Такие правки делаются через Edit, а не через Bash.
5. **Rate limit на весь `/api/auth/`** задевал `GET /me`, который SPA вызывает на каждой загрузке.
   Найдено сквозной проверкой через nginx; строгий лимит оставлен только на проверку пароля.

## Ревью и аудит

Каждый шаг проходил `reviewer`, шаги 2–3 ещё и `security-auditor`. Главные находки, все исправлены:

| Шаг | Находка | Исправление |
|---|---|---|
| 1 | Устаревший worker мог перезаписать результат перехватившего задачу | Fencing-токен `locked_by`, контракт очереди в docstring модели |
| 1 | Нет индекса `jobs(video_id)` для каскадного удаления | Добавлен |
| 2 | Гонка регистраций определялась по подстроке «email», любой IntegrityError маскировался под «имя занято» | Сопоставление по имени ограничения |
| 2 | Тест «выход только текущей сессии» проходил при любом исходе | Проверяет статус, удаление текущей и жизнь другой |
| 2 | DoS по памяти через argon2 (64 МиБ на вызов) — **Medium** | Не больше двух вычислений одновременно на процесс, лимит длины пароля в `/token` |
| 2 | Подложенная cookie `csrf` с другого порта того же IP | CSRF = HMAC(SECRET_KEY, сессия) |
| 3 | Два админа, понижающие друг друга, оставляли систему без администраторов | Advisory-блокировка + повторное чтение роли |
| 3 | Захват имени администратора на развёрнутом стенде — **High** | Строгий bootstrap, зарезервированные имена, пароль печатается только при фактическом создании |

**Мутационные проверки** (ломаем код и смотрим, падает ли тест):
- CSRF, отзыв сессии при выходе, `eager_defaults` — тесты ловят;
- **тест гонки ролей не ловил** (проходил без исправления). Заменён детерминированным
  с двумя транзакциями, который падает и без блокировки, и без повторного чтения роли.

### Найдено при проверке и исправлено после отчёта

- **Хэш вместо имени образа в `docker compose ps`.** Provenance-attestation на containerd image
  store дают новый ID образа при каждой сборке. Итог: лишнее пересоздание контейнеров на каждом
  деплое без изменений кода. Воспроизведено и измерено (`docs/deploy-testing.md`).
  Первое исправление — ключи `build.provenance/sbom: false` в compose — **не сработало**:
  compose 2.40 их принимает, но в сборку не передаёт. Это выяснилось на реальной сборке,
  `docker compose config` проблему не показал. Рабочее исправление — `BUILDX_NO_DEFAULT_ATTESTATIONS=1`
  в `deploy.sh`; плюс удаление прежних образов проекта по ID для классического хранилища.
- **Swagger описывал 422 стандартной схемой FastAPI** (`detail` — список), а реальный ответ —
  `detail` строкой и `errors` списком. Схема `HTTPValidationError` переопределена для всего
  приложения; тест сверяет схему с реальным ответом и проверяет все эндпоинты.
- **Сеть Docker после проверки в yt-clean.** После `systemctl start docker` контейнеры не видели
  друг друга: `dockerd` из yt-clean перестроил общие правила сети. Процедура дополнена:
  `wsl --terminate yt-clean`, затем `systemctl restart docker`.
