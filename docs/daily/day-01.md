# День 1 — 2026-11-07: инфраструктура, деплой, CI, обвязка ИИ

## Цель дня

Скелет, который разворачивается одной командой: compose-стек, health-эндпоинты, CI,
агентная обвязка, документация решений. Критерий: `/api/health` = 200 на свежем стеке
и проверка на чистой ВМ.

## Что сделано

| Область | Результат |

| Стек | postgres 17.10, silo (S3), nginx-unprivileged, api, worker (каркас), одноразовые `migrate` и `storage-init`. Наружу открыт только порт `web` |
| Backend | FastAPI: слои routes/services/repositories; `/api/health/live` и `/api/health` (БД и хранилище, 503 при сбое); async SQLAlchemy, Alembic; worker с корректной остановкой по SIGTERM |

| Документы | `architecture.md` (критерии K1–K8), ADR 0001–0006, `security.md`, `db.md` |

## Решения

Утверждены архитектором до начала работы: React + Vite + TS; MP4 360p/720p; очередь в Postgres;
серверные сессии в cookie; видимость public/unlisted/private со списком допуска,
модераторы и админы видят приватные; Ubuntu 24.04, HTTP по IP; демо-видео через ffmpeg;
лимиты 2 ГБ и 60 минут; русский интерфейс.

Приняты в течение дня:
- **Хранилище — `pgsty/silo` вместо MinIO** (ADR 0002). Решение архитектора по опыту прошлого проекта.
- **Presigned URL подписываются на Host запроса** (ADR 0004): не нужен ни `PUBLIC_HOST`, ни CORS,
  работает по любому IP ВМ.

## Проблемы и как решены

1. **Образы MinIO недоступны.** `minio/minio` отвечает `denied`, `quay.io/minio` требует авторизации.
   Агент предложил варианты, архитектор выбрал `pgsty/silo`. Проверено вручную: образ, `mc`,
   admin-команды, идемпотентность, presigned через nginx.
2. **Конфликт сборки.** `api` и `migrate` параллельно собирали один тег образа. Теперь `migrate`
   использует образ `api` без своей сборки.
3. **Ruff и кириллица.** Правила RUF001–003 срабатывали на русские комментарии, отключены осознанно.

## Ревью

Перед коммитами отработали субагенты `reviewer` и `security-auditor`. Важные находки, все исправлены:

| Находка | Исправление |
|---|---|
| Проверка портов в CI проходила всегда (неверный формат вывода) | Проверка по `docker compose config` через jq |
| `proxy_set_header` в location отменял заголовки уровня server, поэтому подделанный `X-Forwarded-For` доходил до приложения | Все заголовки на уровне server, XFF = `$remote_addr`; проверено: `6.6.6.6` не доходит |
| Хранилище на том же origin: загруженный HTML мог бы выполниться | CSP `sandbox`, методы ограничены (raw — только PUT, media — только GET), фильтр сырого URI |
| Приложение ходило в БД суперпользователем | Роль `yt_app`; проверено: `CREATE TABLE` и `COPY TO PROGRAM` запрещены |
| Тесты писали бы в боевую БД | Отдельные `yt_test` и `yt-test-*` |
| deploy на свежей ВМ: блокировка dpkg, гонка healthcheck postgres, нет логов при сбое | `DPkg::Lock::Timeout`, `pg_isready -h 127.0.0.1`, диагностика при ошибке `up` |
| Документация ссылалась на несуществующие файлы | Созданы `security.md`, `db.md` |

Отложено решением архитектора на день 6: Swagger без CDN, закрепление Actions и образов по хэшу.
Права в `.claude/settings.json` ужесточены после подтверждения архитектора.
