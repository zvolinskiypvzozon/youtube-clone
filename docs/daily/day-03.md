## Решения архитектора

- Исходник после обработки **удаляется** (диск ВМ ограничен, переобработка в другие качества
  не планируется) — в том числе для непригодных файлов.
- Части загрузки по 16 МиБ; не больше 3 видео «в работе» на пользователя.
- `visibility` в API обязательна; в форме по умолчанию «Открытый доступ».

## Проблемы и как решены

1. **502 после пересоздания одного `api`.** Вскрылось как следствие исправления stable image IDs:
   `web` перестал пересоздаваться на каждом деплое, а nginx разрешал имя `api` один раз при старте.
   Раньше это маскировалось лишними пересозданиями. Решение — `resolver 127.0.0.11` и `server … resolve`.
2. **Ключи `provenance/sbom` в compose не действуют** (compose 2.40 принимает, но не передаёт
   в сборку) — выяснено только на реальной сборке, `docker compose config` проблему не показал.
3. **Затёрта незакоммиченная правка через `git checkout -- <файл>`** при откате пробной строки.
   Восстановлено; правило 9 в CLAUDE.md и `git checkout/restore/stash/clean` в `ask`.
4. **Мутационные проверки, которые «проходили»** по трём разным причинам:
   - мутация не применилась (команда упала раньше) → правило: проверять `grep`/`diff` копии;
   - гонка через `asyncio.gather` по ASGI не воспроизводится → детерминированные тесты
     с двумя транзакциями (complete, лимит загрузок, роли);
   - защита продублирована → мутировать все копии разом.
   Все три урока — в `test-writer` и правиле 11 CLAUDE.md.
5. **Собственные ошибки дизайна worker, найденные до ревью:** ключи результатов совпадали
   у разных попыток (устаревший worker удалил бы файлы перехватившего задачу) → токен попытки
   в ключе; объекты, загруженные до перехвата задачи, терялись из учёта.
6. Heredoc с телом, содержащим строку `EOF`, обрывался — Python не запускался (без побочных
   эффектов); для таких правок — другой разделитель.

## Ревью и аудит

| Шаг | Находка | Серьёзность | Исправление |
|---|---|---|---|
| 1 | DoS хранилища: presigned UploadPart не ограничивал длину — «заявить 2 ГБ» = до 16 ГиБ | **High** | Длина части в подписи (silo отклоняет ±1 байт), nginx 17 МиБ на `/yt-raw/` |
| 1 | Гонка лимита загрузок | Medium | Блокировка строки канала |
| 1 | Сбой между склейкой и commit — загрузку не завершить и не отменить, объект 2 ГБ навсегда | Medium | Идемпотентный `complete`, `cancel` удаляет и склеенный объект |
| 1 | Подписи и uploadId в access log; кривой Host → 500 и зависшая загрузка | Low | Лог без query; проверка Host до подписи; подпись до commit |
| 2 | Секреты worker через ffmpeg: PID 1 — сам worker с тем же uid, пустое окружение ffmpeg `/proc/1/environ` не защищало (docstring обещал обратное) | **High** | `PR_SET_DUMPABLE=0` (проверено: без него секрет читается), белый список кодеков, `cap_drop: ALL`, `no-new-privileges`, лимиты памяти и процессов |
| 2 | «Лживая» длительность обходит лимит 60 минут; бомбы по памяти | Medium | `-t` при транскоде; ≤ 4K, ≤ 16 дорожек, ≤ 120 fps; потоки декодера ограничены |
| 2 | GPS и название исходника в публичном файле | Medium | `-map_metadata -1` (проверено на стеке) |
| 2 | Один пользователь занимает очередь worker-а | Medium | Лимит считает `uploading` + `processing` |
| 2 | Утечка объектов при SIGTERM; неоднозначный commit → `ready` с 404; временные файлы до 2 ГБ после падения | Medium | Уборка при отмене; не удалять после начала commit + чистка сирот; уборка `/tmp` при старте |

Принятые риски (в `docs/security.md`): остаточный RCE в декодере ffmpeg (смягчён; полная изоляция
ffmpeg в отдельном контейнере — возможное развитие), нет лимита CPU у worker, drefs mov выключены
по умолчанию ffmpeg, а не явно; TTL ссылок на загрузку 1 час.
