# YouTube Clone — инструкции для ИИ-агента

Тестовое задание: копия YouTube. **Весь код пишет ИИ**, человек — архитектор и ревьюер:
принимает решения, проверяет результат, даёт команду на коммит.

## Порядок работы (обязателен)

1. Новая фича → сначала короткий план (что меняется, какие критерии приёмки, какие тесты) → ждать одобрения.
2. Реализация вместе с тестами. Затем прогнать `reviewer` (и `security-auditor`, если затронуты
   доступ, аутентификация, загрузка или раздача файлов).
3. Показать сводку изменений и предлагаемые сообщения коммитов → **коммит только после ответа "ОК"**.
4. **Со 2-го дня — коммит после каждого проверенного шага** (тесты зелёные, ruff чистый, ревью
   пройдено), а не пачкой в конце дня. Каждый коммит оставляет репозиторий рабочим.
5. Коммиты — Conventional Commits (`feat(api): …`, `fix(worker): …`, `docs: …`), мелкие и
   осмысленные, одна логическая единица на коммит. Историю не переписывать, `--force` запрещён.
   Находки ревью после коммита — отдельными `fix:`-коммитами.
6. Push делает человек (remote по SSH). Агент не пушит.
7. Архитектурные решения фиксировать в `docs/adr/NNNN-*.md`. Не пересматривать принятые ADR без запроса.
8. В конце дня — отчёт `docs/daily/day-NN.md`: что сделано, решения, проблемы, проверки, что дальше.

## Архитектура (кратко, подробно — docs/architecture.md)

- `web` — nginx (unprivileged): SPA, проксирование `/api`, `/docs`, и presigned-доступ к бакетам
  `/yt-raw/*`, `/yt-media/*`. Единственный опубликованный порт.
- `api` — FastAPI. Слои: `api/routes` (HTTP) → `services` (бизнес-логика) → `repositories` (SQL).
  Роуты не ходят в БД напрямую.
- `worker` — фоновая обработка видео (ffprobe/ffmpeg), очередь в Postgres (`FOR UPDATE SKIP LOCKED`).
- `postgres` — метаданные. `storage` — pgsty/silo (форк MinIO), только S3 API через boto3.
- `migrate` (alembic) и `storage-init` (бакеты, пользователь приложения) — одноразовые сервисы.

## Ключевые правила

- **Доступ к видео проверяется только через `app/services/policies.py`** (`can_view` и SQL-фильтр
  видимости для списков). Любой новый эндпоинт, отдающий видео/комментарии/плейлисты/URL файла,
  обязан использовать политику и иметь тест на приватное и скрытое видео.
- Бинарные данные — только в хранилище; в БД — ключи объектов и метаданные.
- Бакеты закрыты. Браузер получает только presigned URL с коротким TTL после проверки прав.
- Секреты — только из переменных окружения (`app/core/config.py`). Никогда не читать и не выводить `.env`.
- Пароли — argon2. Сессии — серверные, cookie `HttpOnly; SameSite=Lax`.
- Все тексты интерфейса — на русском. Идентификаторы, API и сообщения коммитов — на английском,
  описания коммитов можно на русском.
- Версии зависимостей и образов закреплены (образы — до patch-версии). Никаких `latest`; новые версии — не моложе двух недель.

## Команды

```bash
./deploy.sh                                          # полный деплой (Ubuntu 24.04)
docker compose up -d --build                         # локальный стек
docker compose --profile test build && docker compose --profile test run --rm tests   # pytest (БД yt_test, бакеты yt-test-*)
python3 -m venv .venv && .venv/bin/pip install ruff==0.11.8   # один раз: ruff для хука и локальной проверки
.venv/bin/ruff check backend && .venv/bin/ruff format backend
cd frontend && npm run build                          # typecheck + сборка SPA
```

## Definition of Done

- Есть тесты на критичное поведение (доступ, роли, граничные случаи), `pytest` зелёный.
- `ruff check` и `ruff format --check` чистые, фронт собирается (`npm run build`).
- Стек поднимается `docker compose up -d --build`, `/api/health` = 200.
- Обновлены docs (architecture, db, security, ADR), если изменилось поведение или схема.
- Миграция Alembic есть для каждого изменения моделей и проходит `upgrade` на пустой БД.
