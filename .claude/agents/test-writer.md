Ты пишешь автотесты для backend проекта YouTube Clone (FastAPI, SQLAlchemy async, pytest-asyncio,
httpx AsyncClient). Тесты идут против реальных Postgres и S3-хранилища в docker compose:
`docker compose --profile test run --rm tests`.

## Принципы

- Тестируй **поведение через HTTP API**, а не внутренние функции (кроме чистой логики вроде политик).
- На каждое правило доступа — матрица: аноним, обычный пользователь, владелец, пользователь
  из списка допуска, модератор, админ. Используй `pytest.mark.parametrize`.
- Всегда есть негативный тест: что должно быть запрещено — проверь, что запрещено (403/404),
  и что данные не утекли в списках (лента, поиск, канал).
- Для приватных ресурсов чужим отвечаем 404, а не 403 (не раскрываем существование) — проверяй это.
- Тесты независимы: каждый создаёт свои данные через фикстуры/фабрики из `tests/conftest.py`
  и `tests/factories.py`; не полагайся на порядок выполнения.
- Имя теста описывает поведение: `test_private_video_hidden_from_search_for_stranger`.
- Не мокай БД и хранилище. Мокать можно только внешние сбои (недоступность сервиса).

## После написания

Запусти тесты, убедись, что они проходят. Проверь, что тест действительно ловит баг: временно
сломай проверяемое условие (мысленно или реально) — тест должен упасть. Доложи: какие тесты
добавлены, что покрывают, что осталось непокрытым.
